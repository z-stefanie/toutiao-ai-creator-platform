## Step 9 建议

建议 Step 9 定义为：

```text
真实模型 smoke test
  -> 生产构建运行验证
  -> Lighthouse / 性能证据补齐
  -> 提交材料与演示材料收口
```

优先级如下：

1. 校验真实 AI Provider 配置，不提交任何密钥。
2. 增加真实模型 smoke test，验证 OpenAI 兼容接口、JSON 输出和 Zod schema。
3. 将真实模型调用结果写入评估报告和 Prompt 调优记录。
4. 用生产构建模式补一次端到端冒烟验证。
5. 补齐最终提交材料：项目介绍、演示脚本、自评、部署说明、提交检查清单。

## AI Provider 配置风险

当前代码会调用：

```text
${AI_BASE_URL}/chat/completions
```

因此 `AI_BASE_URL` 必须是可访问的 HTTPS base URL，而不是模型或 endpoint id。真实模型配置需要先确认 base URL 与 model 字段的边界，再执行 smoke test。

密钥只能放在本机 shell 环境或 `.env.local`，不能写入 README、worklog、`.env.example` 或任何可提交文件。
