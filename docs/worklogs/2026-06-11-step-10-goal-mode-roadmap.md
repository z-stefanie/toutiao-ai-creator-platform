
## 可拆分子 Goal

### Goal A：部署与线上性能证据

目标：

```text
完成项目部署或生产模式可访问验证，并补齐 Lighthouse / 浏览器性能证据，证明榜单首屏满足 LCP 2.5 秒目标。
```

验收标准：

- 有线上 URL 或等价可访问环境说明。
- 生产构建启动成功。
- 至少记录一次榜单页 Lighthouse 或浏览器 Performance 结果。
- `docs/evaluation-report.md` 更新部署环境 LCP 结果。
- `README.md` 更新部署与环境变量说明。

### Goal B：最终提交文档包

目标：

```text
补齐训练营提交模板要求的项目介绍、技术文档、自评、部署说明和提交检查清单。
```

验收标准：

- 新增或完善 `docs/project-introduction.md`。
- 新增或完善 `docs/project-self-review.md`。
- 新增或完善 `docs/deployment-guide.md`。
- 新增或完善 `docs/submission-checklist.md`。
- 文档能清楚解释：完成了什么、如何运行、如何验证、已知边界、下一步优化。

### Goal C：演示视频脚本与录制准备

目标：

```text
整理 3-5 分钟演示视频脚本和录制路径，让演示覆盖主链路、违规分支、进阶挑战和技术亮点。
```

验收标准：

- 新增 `docs/demo-script.md`。
- 脚本包含时间轴、页面路径、点击动作、解说词和预期画面。
- 演示路径不依赖真实模型长耗时，默认使用 Mock Provider。
- 脚本包含真实模型 smoke test 作为技术验证证据，但不把它放进现场主链路。

### Goal D：代码提交与仓库清理

目标：

```text
完成提交前工程清理，确保代码、文档、验证脚本、Git 状态和敏感信息都满足提交要求。
```

验收标准：

- `git status` 中没有非预期 unstaged 变更。
- 不提交 `.env.local`、数据库文件、构建产物、测试报告和 API Key。
- 最终验证命令通过。
- 可以形成一次清晰的初始提交。
- 提交清单能映射到训练营模板要求。

## 推荐执行顺序

推荐按以下顺序执行：

1. Goal B：先补最终提交文档包，明确要讲什么。
2. Goal C：基于文档抽出演示脚本，形成 3-5 分钟叙事。
3. Goal A：部署和补 Lighthouse，把线上证据填回文档。
4. Goal D：最终清理、验证、提交。

如果只能开一个 Goal Mode，建议使用 Goal 1 作为总目标；如果希望降低上下文和执行风险，按 A/B/C/D 四个子 Goal 顺序推进。
