# 项目介绍文档

## 1. 项目简介

「头条 AI 创作者辅助生产与分发平台」是一个面向内容创作者的 AI 辅助生产与分发系统。项目目标不是单点调用大模型 API，而是跑通一条可演示、可验证、可解释的内容链路：

```text
灵感输入
  -> AI 生成短图文草稿
  -> 人工编辑与局部重写
  -> 草稿保存与离线同步
  -> 发布前安全审核
  -> 合规改写
  -> 质量评分
  -> 发布进入热点 / 爆文 / 推荐榜单
  -> 内容详情页解释排序原因
```

当前版本优先交付训练营课题要求的端到端闭环，并在关键位置保留工程证据：结构化 AI 输出、AI 调用日志、审核样例集、质量评分样例、E2E 测试、线上 Performance 记录和真实模型 smoke test。

## 3. 核心功能

### 3.1 用户中心

已实现登录、注册、退出和受保护页面访问控制。MVP 使用 Mock 认证，HttpOnly Cookie 保存本地会话。演示账号统一使用：

```text
demo@toutiao.ai / demo123456
```

### 3.2 AI 内容创作

创作者可以在 `/create` 输入主题、受众和风格，选择 Prompt 与素材，生成结构化短图文草稿。生成结果包含：

- 标题。
- 摘要。
- 正文。
- 封面建议。
- AI 配图建议。
- 标签。
- 推理摘要。

生成后进入 `/editor/[draftId]`，支持人工继续编辑、段落卡片、单段局部重写、保存草稿和发布。

### 3.3 草稿与离线同步

编辑器支持：

- 在线保存草稿。
- IndexedDB 本地草稿镜像。
- 离线编辑时标记 `local_pending`。
- 网络恢复后同步服务端。
- 发布后从详情页重新进入编辑器，二次编辑并更新线上内容。

当前实现面向单用户、单设备演示场景；多设备冲突合并仍属于后续增强。

### 3.4 内容 AI 审核与合规改写

发布前会执行安全审核。当前覆盖：

- 涉黄。
- 涉赌。
- 涉毒。
- 敏感信息。
- 低俗内容。

审核结果包含通过状态、风险等级、风险分类、命中片段、处置动作和修改建议。命中高危风险时会阻止发布，并提供“一键合规改写”。

当前默认演示使用 Mock Provider 和规则预筛，保证演示稳定；真实模型接入已通过 OpenAI-compatible smoke test 验证。

### 3.5 质量评分与分发排序

内容通过审核后，会获得质量评分。评分维度包括：

- 原创性。
- 结构完整度。
- 可读性。
- 信息密度。
- 标题吸引力。
- 图文匹配度。

质量分会进入榜单排序。当前支持三类榜单：

| 榜单 | 排序侧重点 |
| --- | --- |
| 热点榜单 | 综合质量、热度、新鲜度和反馈 |
| 爆文榜单 | 强化实时热度和用户反馈 |
| 推荐榜单 | 强化质量分和反馈信号 |

内容详情页会展示排序解释，包括质量分、热度分、新鲜度、反馈分和当前榜单权重。

### 3.6 内容治理

项目实现了最小内容下线 API：已发布内容可被置为 `offline`，下线后不再进入榜单和详情消费。恢复、撤回、回滚和人工复核队列属于后续增强方向。

## 4. 产品亮点

### 4.1 主链路完整

项目没有把 AI 能力停留在“生成一段文本”，而是把 AI 生成、人工编辑、审核、改写、评分、发布、排序和详情解释串成一条可跑通的产品链路。这个选择能更直接回应课题中的“创作、审核、分发、反馈、优化”闭环。

### 4.2 AI 输出可控

四类 AI 能力都经过结构化 schema：

- `generate_content`
- `audit_content`
- `rewrite_compliant`
- `score_quality`

服务端使用 Zod 校验输出，并将调用类型、provider、模型、耗时、输入摘要、输出摘要和 schema 结果写入 `AiCallLog`。这让 AI 行为可追踪、可复盘，也方便后续做 Prompt 版本评估。

### 4.3 人机协同明确

编辑器不是简单展示 AI 结果，而是允许创作者逐段确认、局部重写、接受或拒绝合规改写，再提交审核发布。AI 的角色是降低初稿和合规修改成本，人仍保留最终确认权。

### 4.4 分发排序可解释

榜单不是黑盒排序。系统会展示不同榜单的运营权重，并在详情页解释当前内容的质量、热度、新鲜度和反馈信号。这样既能服务读者浏览，也能让创作者理解优化方向。

### 4.5 证据链完整

项目保留了从开发到提交的证据：

- `README.md`：启动、演示、验证说明。
- `docs/audit-and-quality-system.md`：审核与评分体系。
- `docs/evaluation-report.md`：eval、真实模型 smoke test、线上 Performance。
- `evals/`：审核样例、质量样例、Prompt 调优记录。
- `tests/e2e/mvp-flow.spec.ts`：主链路和关键分支 E2E。
- `docs/worklogs/`：阶段性技术留存。

## 6. 演示建议

建议 3-5 分钟演示视频按以下顺序录制：

1. 登录并进入工作台。
2. 在 `/create` 输入主题并生成草稿。
3. 在编辑器查看封面建议、配图建议和段落卡片。
4. 点击局部重写，展示人机协同。
5. 发布正常内容，进入热点榜单和详情页。
6. 在正文中加入风险词，展示审核拦截和合规改写。
7. 展示 hot / viral / recommended 不同权重和详情页排序解释。
8. 简要展示 README 或评估报告中的真实模型 smoke test 与线上 LCP 证据。

## 7. 当前边界

- 认证是 Mock 认证，适合训练营演示，不包含真实短信、邮箱验证码和密码加密体系。
- 数据库当前为本地 SQLite，架构上通过 repository 隔离，后续可迁移 PostgreSQL。
- 素材上传当前使用演示素材和基础合规状态，未接入对象存储。
- 默认 AI Provider 为 Mock，保证演示稳定；真实模型 smoke test 已验证四类任务 4/4 通过，但真实模型耗时明显更长。
- 审核样例集内结果可作为基线，不应直接等同线上真实泛化准确率。
- 当前在线地址为 Cloudflare quick tunnel 临时地址，不等同长期生产部署。
