# 审核规则与质量评估体系

## 1. 目标

本体系服务于“AI 创作 -> 发布前审核 -> 质量评分 -> 分发排序”的主链路，目标是让内容治理和内容分发都可解释、可验证、可持续优化。

当前 MVP 使用 Mock Provider 保证演示稳定，但审核输出、质量评分输出和 evals 样例都按真实模型接入后的结构设计。

## 2. 安全审核规则库

### 2.1 覆盖范围

| 风险类型 | category | 当前识别样例 | 处置原则 |
| --- | --- | --- | --- |
| 涉黄 | `porn` | `涉黄`、`色情`、`成人内容`、`裸露`、`黄色网站` | 高危拦截，要求改写或人工复核 |
| 涉赌 | `gambling` | `赌博`、`博彩`、`赌局`、`下注`、`赔率`、`彩票套利` | 高危拦截，要求改写 |
| 涉毒 | `drug` | `毒品`、`禁药`、`吸毒`、`贩毒`、`违禁药物` | 高危拦截，要求改写 |
| 敏感信息 | `sensitive` | `敏感信息`、`身份证`、`手机号`、`家庭住址`、`银行卡`、`密码` | 高危拦截，要求改写或人工复核 |
| 低俗内容 | `vulgar` | `低俗`、`擦边`、`粗俗`、`恶俗`、`挑逗` | 高危拦截，要求改写或人工复核 |
| 其他风险 | `other` | 预留 | 进入人工复核或规则补充 |

### 2.2 审核输出结构

审核结果必须包含：

- `passed`：是否通过。
- `riskLevel`：`none`、`low`、`medium`、`high`。
- `categories`：命中的风险类型。
- `hitSpans`：命中片段、类型和原因。
- `action`：`allow`、`warn`、`block`、`rewrite_required`。
- `suggestion`：给创作者的处理建议。

所有输出通过 `auditOutputSchema` 做 Zod 校验，避免模型返回不可控文本直接进入业务链路。

### 2.3 风险等级与处置动作

| 风险等级 | 判定说明 | 处置动作 |
| --- | --- | --- |
| `none` | 未命中风险规则 | 允许进入质量评分和发布 |
| `low` | 轻微表达风险或信息不充分 | 提示修改，可继续发布 |
| `medium` | 存在明显风险但可通过编辑修复 | 建议改写或人工确认 |
| `high` | 命中涉黄、涉赌、涉毒、敏感信息、低俗等高危内容 | 自动拦截，要求合规改写 |

MVP 中命中当前规则库即判定为 `high`，`action=rewrite_required`。规则预筛层位于 `src/server/audit/rule-prescreen.ts`，每条命中还会给出 `machine_blocked` 或 `manual_review_required` 的治理状态建议。

## 3. 合规改写策略

合规改写不是简单删除整篇内容，而是在保留原意的前提下替换高风险片段。

输出结构：

- `title`：改写后的标题。
- `body`：改写后的正文。
- `changedSpans`：每个替换片段的 `before`、`after` 和 `reason`。

创作者可以在编辑器确认改写结果，再次提交审核和发布。

## 4. 质量评分体系

### 4.1 评分维度

| 维度 | 字段 | 评估说明 |
| --- | --- | --- |
| 原创性 | `originality` | 是否具备独立观点或具体表达 |
| 结构完整度 | `structure` | 是否有清晰开头、展开和结尾 |
| 可读性 | `readability` | 是否适合信息流快速阅读 |
| 信息密度 | `informationDensity` | 是否包含足够事实、步骤、案例或解释 |
| 标题吸引力 | `titleAttraction` | 标题是否清楚、具体、有点击动机 |
| 图文匹配度 | `imageTextMatch` | 图片或素材是否支持正文主题 |

### 4.2 分数段

| 分数段 | 解释 | 当前 eval 桶 |
| --- | --- | --- |
| 88-100 | 高质量，结构充分、信息密度较高，可优先进入分发 | `high` |
| 82-87 | 普通质量，表达完整但案例或信息密度有限 | `medium` |
| 70-81 | 低信息量，适合提示创作者继续补充 | `low` |

当前 Mock 评分用于演示和评估闭环，真实模型接入后需要用人工标注样例校准分数段。

### 4.3 排序使用方式

质量总分进入榜单排序公式。当前实现不是单一榜单权重，而是按榜单类型使用不同运营配置：

```text
activeRankingScore =
  qualityScore * qualityWeight
  + heatScore * heatWeight
  + freshnessScore * freshnessWeight
  + feedbackScore * feedbackWeight
```

当前权重：

| 榜单 | 质量 | 热度 | 新鲜度 | 反馈 |
| --- | --- | --- | --- | --- |
| 热点榜单 hot | 40% | 30% | 20% | 10% |
| 爆文榜单 viral | 20% | 45% | 10% | 25% |
| 推荐榜单 recommended | 55% | 15% | 15% | 15% |

详情页展示质量分、热度分、新鲜度、反馈分和当前榜单权重，帮助创作者理解内容分发结果。

## 5. 评估样例

样例位于 `evals/`：

- `evals/audit-cases.json`：33 条审核样例，覆盖正常、涉赌、敏感、低俗、涉毒、涉黄。
- `evals/quality-cases.json`：3 条质量样例，覆盖 high、medium、low 三个分数段。
- `evals/prompt-iterations.md`：Prompt 版本与调优记录。

运行：

```bash
npm run evals
```

当前基线结果：

```text
Audit cases: 33/33 (100.0%)
Quality cases: 3/3 (100.0%)
Eval schema failures: 0
AI call log schema success: 100.0%
```
